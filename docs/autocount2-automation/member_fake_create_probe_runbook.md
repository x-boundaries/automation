# AC2 Member Fake Create Probe Runbook

Status: explicit opt-in local write probe only. This is the first write-capable probe in the member-intake workstream.

## Purpose

`scripts/ac2_member_fake_create_probe.ps1` proves whether AutoCount accepts `SaveMember(MemberEntity)` after the already-proven auth, `MemberCommand.Create`, `GetNextMemberNo`, `NewMember(false)`, and synthetic row assignment path.

This probe writes exactly one fake member. It creates one fake member in AutoCount only when all write opt-ins are supplied:

- `-EnableMemberFakeCreateProbe`
- `-ConfirmAutoCountWrite`
- `-ConfirmSyntheticDataOnly`
- `-ConfirmSingleFakeMember`

## Safety Boundary

This is the first write-capable probe. It creates one fake member in AutoCount.

Run only on the approved test/pre-go-live account book. Do not run on production without explicit business approval.

It uses synthetic fake data only. It does not use real customer/member data.

It does not read existing member/customer records. It does not browse members. It does not delete or cleanup automatically.

Manual cleanup may be needed in AutoCount UI after verification.

Generated output stays local and is not committed. Share only sanitized summary.

The probe must not be wired to Google Form, n8n, batch input, or external payload files. It uses the one hard-coded fake member payload documented by this runbook.

## Fake Member Payload

The single synthetic member uses:

- `MemberNo`: generated by `GetNextMemberNo()`
- `MemberType`: `Default`
- `Name`: `XB API SAVE PROBE`
- `MobilePhone`: `90000000`
- `EmailAddress`: `xb.api.save.probe@example.invalid`
- `DOB`: `1990-01-01`
- `RegisterDate`: `2026-01-01`
- `Note`: `XB_AUTOMATION_FAKE_CREATE_PROBE_DELETE_ME`
- `OpeningPoints`: `0`

`IsActive` and `Individual` keep the existing row value when present, otherwise the probe falls back to `T`.
